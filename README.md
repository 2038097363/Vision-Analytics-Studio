# Vision Analytics Studio

**本地优先的 Windows 图片智能分析工作台。** 在一个桌面应用中完成虚拟穿搭、设备相册整理、植物观察和实验室二维图像分析；图片与视觉模型默认留在用户电脑，云端只作为可选的账户和同步控制面。

## 项目亮点

| 模块 | 当前能力 |
| --- | --- |
| 虚拟穿搭 | FASHN VTON 本地生成、服装与人物语义预检、原图／结果滑块对比、左右手臂独立核验、实验性局部手部修复与肤色校正 |
| 个人相册 | 只扫描用户授权目录、本地缩略图与安全类别分类、低置信度图片进入独立未分类图库、人工批量修订 |
| 植物与农业 | BioCLIP 本地 Top-3 候选、有限物种范围、未知类与证据不足提示、人工确认和观察历史 |
| 实验室图像 | CPU 阈值分割与分水岭、二维对象计数、面积和等效直径、尺度记录、轮廓与参数追溯 |
| 账户与数据 | FastAPI＋PostgreSQL 生产结构、Argon2id、刷新令牌轮换；图片默认不上传，设备绝对路径不进入云端 |

## 技术架构

```text
Tauri 2 / Rust 主进程
├─ React 19 + TypeScript 桌面界面（Windows WebView2）
├─ SQLite 本地素材、任务与离线索引
├─ Python JSONL 视觉引擎（CUDA / CPU）
│  ├─ FASHN VTON + 人体解析 + 手部局部修复
│  ├─ MobileNetV3 相册安全分类
│  ├─ BioCLIP 植物候选
│  └─ OpenCV / SciPy 实验图像分割
└─ 可选 FastAPI / PostgreSQL 账户服务
```

项目不需要 ChromeDriver 或 Selenium。Tauri 使用系统 WebView2 渲染桌面界面，视觉推理通过本地 Python 子进程执行；2 核 4GB 等轻量服务器只计划承载认证、元数据和任务控制，不承担 GPU 推理。

## 快速开始

开发环境需要 Windows 11 x64、Node.js、Rust MSVC 工具链和 Python。仅浏览界面不要求安装大模型；运行对应视觉功能时，再按 `models/*/README.md` 放置经过校验的模型文件。

```powershell
npm install
npm run desktop:dev
```

完整工程检查：

```powershell
npm run check
```

已经在本机编译过时，也可以双击项目根目录的 `启动 Vision Analytics Studio.cmd`。当前 EXE 仍依赖项目目录中的 Python 源码、运行时和按需模型，不应把单个 EXE 复制到其他电脑当作完整发行包。

## 数据与隐私原则

- 默认本地处理和本地保存；导入图片不会自动同意外发。
- 设备相册只读取用户明确授权的目录，不做人脸身份、证件文字、健康、宗教、政治或精确位置等敏感推断。
- 模型权重、运行时、用户图片、生成结果、数据库、日志和 `.env` 均不进入 Git 仓库。
- 虚拟穿搭生成的是合理外观，不承诺真实尺码，也不能还原被衣服遮挡的真实皮肤、纹身、伤痕或饰品。

详细的产品边界、模型成本、云端安全和发行路线见 [`docs/`](docs/)。建议从 [整体架构](docs/00-overall-architecture.md)、[虚拟穿搭](docs/02-virtual-try-on.md)、[模型与成本](docs/06-models-and-cost.md) 和 [下一阶段升级清单](docs/09-next-upgrades.md) 开始阅读。

## 0. 当前可运行版本

仓库已经具备 Tauri 2＋React/TypeScript＋Rust＋Python 的最小闭环，并在当前 Windows 开发机完成真实桌面窗口启动。现有功能包括：

- 首次启动引导与开发阶段本地工作区；桌面登录框已能连接真实账户 API 完成注册、登录和退出，本机 SQLite 保存设备缓存和离线索引。
- 首页、四个业务工作区、任务中心、模型中心和设置的桌面导航框架。
- 本机 GPU 与显存探测；当前机器可识别为 RTX 5060 Laptop、约 8GB 显存。
- JPEG、PNG、WebP、TIFF 文件选择、格式与 100MB 大小校验、SHA-256 去重依据、原子复制入本地素材库和最近导入记录。
- 虚拟穿搭双图工作区：人物图与服装图分别导入和预览，支持上衣、下装与连衣裙类别、模特图／平铺图选择、20／30 步预设；模型未就绪时明确阻止生成。
- 本地图片预检：真实解码并检查 JPEG/PNG/WebP、15MB 与 2400 万像素上限、短边尺寸、曝光、边缘清晰度和横向人物构图风险。
- FASHN VTON v1.5 隔离运行时：固定源码和三组模型版本，校验文件大小与 SHA-256，桌面端强制离线推理；RTX 5060 Laptop 8GB 已完成 576×864、BF16、20 步真实生成，模型核心约 33 秒，桌面冷启动全链路约 59 秒。
- 穿搭草稿、选项与预检结果持久化：重启后恢复双图输入和生成历史；结果原子写入本地素材库，支持原图／结果滑块对比与历史版本切换，任务记录包含模型版本、分辨率、耗时、类别、步数和种子。
- 可用的任务中心：展示本地任务状态、阶段、检查结论和失败记录；相册扫描与分类任务支持安全取消。
- 设备相册目录授权、后台递归索引、受控本地缩略图、八类可选安全分类、人工与批量归类、分类图库和独立未分类图库；设备照片不会因索引被复制或上传，并可由用户指定为穿搭人物图或服装图。
- MobileNetV3 Small 本地相册粗分类：仅处理本机缩略图，严格映射到已启用的安全类别，低于 35% 或范围外图片保留在未分类；记录模型版本、标签、置信度并保护人工结果。
- BioCLIP 植物观察工作区：固定 20 种常见植物范围，支持图片导入、整株／叶／花／果标注、Top-3 本地候选、人工确认或暂不确认、观察历史和重启恢复；候选分数明确标为未校准排序，不自动写成物种事实。
- BioCLIP ViT-B/16 隔离运行时：固定官方提交与 598,599,013 字节权重，强制离线运行；RTX 5060 Laptop 已完成真实 CUDA 端到端调用，抽象测试图冷启动约 10.3 秒。该测试只验证工程链路，不代表识别准确率。
- 实验室图像工作区：导入二维 PNG/JPEG/单页 TIFF，调节阈值与最小面积、选择是否排除边缘对象、填写可选 μm/px 尺度；CPU 执行 Otsu 阈值、距离变换和分水岭，展示轮廓、核数量、面积、等效直径、对象表和人工复核状态。
- 实验室分析参数、算法版本、原始位深摘要、测量对象、轮廓图和复核状态均写入本地 SQLite；合成 900×700 核图桌面端到端测试正确得到 9 个对象，处理约 1.3 秒。合成结果只验证计算与持久化链路。
- FastAPI 账户服务：PostgreSQL 生产配置、Argon2id、统一登录错误、短期随机访问令牌、刷新令牌轮换与旧令牌重放撤销；开发测试可用一次性 SQLite。
- Rust 后端调用本地 Python JSONL 引擎协议的健康检查，为后续接入试衣和识别模型保留稳定边界。
- 离线 CSP、应用图标、Tauri 权限清单和 Windows MSVC 构建脚本。

## 1. 先看这几个结论

- **做可安装的桌面软件。** 用户从开始菜单启动独立窗口，核心界面与功能本地运行。
- **不需要内置浏览器驱动。** 建议 Tauri 2＋React/TypeScript 界面＋Python 模型进程；Windows 用 WebView2 渲染界面，不需要 ChromeDriver、Selenium 或自动操作免费聊天网站。
- **本地优先，免费视觉 API 可选。** API 适合标签、图片描述与解释；不自动代替试衣生成或显微测量，也不自动转付费。
- **先支持自己的电脑。** 已读取开发机为 RTX 5060 Laptop、约 8GB 显存、16GB 内存。模型按需安装、单 GPU 排队，先实测再承诺速度。
- **商店用户默认使用各自电脑的算力。** 你的电脑只用于开发、自用或限额内测，不作为所有用户共用的免费推理服务器。
- **4 核／2GB 服务器以后按需租。** 承载 HTTPS API 与小规模 PostgreSQL；图片原件走独立对象存储且仅在用户开启同步后上传，服务器不负责 GPU 推理。
- **正式版要求账户。** 首次使用先注册或登录；断网时只开放最近登录用户的受控离线缓存，开发构建保留明确标识的本地旁路以便服务上线前调试。
- **数据库与图片分开。** PostgreSQL 是账户、设置和同步元数据的权威数据源；图片二进制不塞入关系数据库，设备绝对路径永不上传。

## 3. 四个模块的首版目标

| 模块 | 首版能做什么 | 需要专门验证的部分 |
| --- | --- | --- |
| 虚拟穿搭 | 单人正面照＋单件上衣，生成二维效果图，支持前后对比与反馈 | 本机显存、人物与衣服保真、模型/依赖分发许可 |
| 植物与农业 | 20 种起步的有限识别、Top-3 候选、资料与观察记录 | 实拍域偏移、范围外输入拒答、资料来源；农业诊断后续独立验证 |
| 实验室 | 指定二维核图的分割或人工标注、复核、数量和校准尺寸、规则异常 | 核不能直接等于细胞；无尺度只给像素；自动分类与生物学异常需专用数据 |
| 个人相册 | 经授权索引设备照片，按用户选择的安全类别在本地整理；未判断图片进入独立未分类图库 | 不扫描未授权目录、不推断敏感属性、不误删外部原图、近重复不自动合并 |

共同底座：素材库、任务中心、设备与模型中心、结果来源、人工修订、存储清理和设置。共同原则：照片默认保留本地、无模型不等于整个软件不可用、AI 结果可修正、生成结果与科学测量有不同验收标准。

## 4. 免费视觉 API 的位置

优先评测国内 BigModel 的免费视觉理解入口；百炼按限时试用管理，Gemini 仅对满足地区和条款条件的用户列为可选。具体型号、免费政策与停止规则均附官方来源，详见 [免费 API 规划](docs/06-models-and-cost.md)。本轮未申请账号或调用这些服务。

免费视觉理解通常输出文字，不等于免费试衣生图。软件只允许已核验的免费型号和满足条件的试用权益；免费用尽、到期或资格不明时停止，回到本地或保留输入等待配置。安装包不包含开发者共享密钥。

## 5. 从想法到发行版的顺序

1. 继续验证桌面外壳、打包 Python 进程和最小 MSIX 路线；本机试衣技术链路已跑通。
2. 建设首次启动、首页、基础相册、任务系统和模型管理。
3. 完成单件上衣试衣闭环，收集真实失败案例并做独立评测。
4. 完成植物观察的受限候选闭环和实验室二维核图 CPU 基线；下一步补齐资料、导出与真实盲测。
5. 将现有账户 API 部署到 PostgreSQL，完成邮箱验证、恢复与客户端系统凭据存储，再按预算增加一个免费 API 适配器；图片同步和远程设备按明确需求开放。
6. 通过安装、升级、卸载、模型许可和功能验收后准备商店提交。

按单开发者全职估算，首个桌面试衣内测版争取约第 8 周；四模块桌面发行准备基线约 19 周，含返工余量约 22–24 周。专业标注、授权、可选云功能和商店审核等待另计，具体阶段见 [路线图](docs/07-release-roadmap.md)。

## 6. 必须提前解决的可行性问题

- 8GB 显存已完成单次真实生成；仍需 30 次连续运行、峰值显存与困难样例测试，不能用单个成功样例代替稳定性结论。
- 研究模型、权重和辅助解析器是否允许实际产品使用与再分发；软件免费不自动解决许可限制。
- Tauri 官方默认打包 EXE/MSI；MSIX 需额外验证，不能承诺一键自动过审。
- 每位用户电脑的硬件可能不同，需要基础功能与 GPU 功能分级。
- 实验室真实样本、对象定义、尺度和标注是否可获得。
- 免费 API 是否适用于用户地区与当前账号，是否允许所需数据用途、是否会自动计费。

当前已从规划进入桌面功能开发，并通过前端构建、Python 与账户测试、Rust 编译、真实桌面窗口以及本地试衣端到端生成。现有数据只证明这台开发机上的单样例技术可行性，尚不代表固定评测集质量、安装包兼容性或商店审核结果。
