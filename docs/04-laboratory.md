# 实验室图像模块规划

> 状态：CPU 基线工程闭环已完成，真实样本质量评测待做；更新于 2026-09-19。限研究图像辅助分析。
> 首发运行于 Windows 桌面，原始图像与测量结果默认保留在用户电脑；共享素材、任务、导出和模型管理。

公共约定见 [整体框架](00-overall-architecture.md)，模型分发与发布条件见 [发布规划](07-release-roadmap.md)。

## 当前实现进度（2026-09-19）

已完成可运行的二维核图工作区：素材导入、原图／轮廓切换、阈值系数、最小核面积、边缘对象筛选、可选 `μm/px` 尺度、分割结果摘要、逐对象测量预览、人工复核状态、任务记录、分析历史和 SQLite 持久化。原始图保存在统一素材库，轮廓预览另存到应用数据目录，重新分析会创建新版本而不覆盖旧结果。

当前算法为 `otsu-watershed-v1`：强度稳健归一化、Gaussian 平滑、Otsu 阈值、形态清理、距离变换、局部峰标记与分水岭。它在 CPU 上运行，不需要模型权重或 API。面积按像素计数；提供可靠尺度时使用 `A = N × s²`，等效直径使用 `2 × sqrt(A/π)`。结果始终标为二维细胞核，界面明确提示核数量不等于细胞数量。

已用包含 9 个已知圆形对象的 900×700 合成核图完成桌面端到端验证，得到 9 个实例，处理约 1.3 秒，并验证轮廓叠加、对象表、复核与历史保存。这只证明确定性算法、计算口径和应用链路正常，不能代替真实荧光图盲测。

尚未完成：真实实验室代表样本与 30 图盲测、16 位／多通道 TIFF 的完整元数据工作流、人工增删拆合与撤销、整数实例标签 TIFF、逐对象 CSV 和汇总 JSON 导出、项目／样本层级、非等距尺度、ROI 和批处理。当前 TIFF 仅接受可明确解码的单页二维输入；任何真实研究结论都应在目标成像条件下单独验证。

## 1. 用户、目标与范围

面向重复进行显微图片计数和尺寸统计的学生、实验人员与研究者。
首版价值是把一类明确图像的“分割 → 复核 → 测量 → 导出”做可靠，同时保存统计口径。
立项先取得目标实验室代表性样本，确认成像方式、染色、对象定义、密度、尺度与预期统计用途。
尚无真实样本时，只能交付指定公开样例的演示，不能宣称适用于任意实验室。

| 版本 | 交付范围 | 进入条件 |
| --- | --- | --- |
| V1 | 边界较清楚的二维细胞核荧光图：实例计数、面积、等效直径、修订、导出 | 有真实标注和统一对象定义 |
| V1.1 | 同一成像配置的批处理、分析预设、人工 ROI 导入 | 单图闭环与尺度检查稳定 |
| V2 | 指定细胞类型分类、明确异常标签、授权模型扩展 | 专用标签集、独立盲测及模型分发条件明确 |
| 暂不支持 | 全切片扫描、3D 体积、Z-stack、视频追踪、通用细胞命名 | 后续独立立项，不隐藏降维 |

“细胞核数量”和“细胞数量”是不同输出：默认核分割只能报告核数量。
单个细胞可能有多个核或看不到核；不能直接把核计数重命名为细胞计数。
分割算法仅提供对象掩膜；细胞生物学名称、活死状态或病理性质不能从分割输出直接得出。
样本类型先由用户选择并标注来源；没有专用分类器时，“自动细胞名称”保持未提供。

## 2. 桌面工作区与操作流程

实验室模块采用左侧项目/图像列表、中间原图和叠加层、右侧通道与参数、底部对象表布局。
支持滚轮缩放、平移、原图/轮廓切换、对象点击高亮、撤销/重做和快捷键提示。

| 步骤 | 界面动作 | 必须保留的状态 |
| --- | --- | --- |
| 新建项目 | 输入样本代号、成像类型、对象是核还是细胞 | 样本代号不要求个人身份信息 |
| 导入图像 | 文件选择器、拖入、相册引用；先读取元数据摘要 | 原图哈希、位深、形状、通道、文件来源 |
| 选通道 | 显示各通道预览，用户明确分析通道 | 通道索引及含义，不能只保存 RGB 颜色 |
| 校准尺度 | 元数据确认或手动画线输入已知长度 | sx、sy、单位、来源和确认人 |
| 运行分割 | 选择经验证的预设，显示排队和阶段 | 算法、模型版本、参数快照 |
| 复核修订 | 增删、拆分、合并、边缘对象筛选、画 ROI | 编辑前后版本和对象继承关系 |
| 统计导出 | 看数量、分布、筛选分母，再确认导出 | 自动结果和复核结果分别保留 |

状态区始终显示“核/细胞”“像素/物理单位”“未复核/已复核”，避免用户误读统计对象。
自动保存编辑草稿；应用异常退出后可恢复草稿，但不把未保存的算法半成品标为完成。
重新分割创建新分析分支，不覆盖上一版人工修订；导出时由用户选择明确版本。
首次没有模型时也可使用尺度校准、手动画对象和测量功能，避免把下载模型作为启动障碍。

## 3. 原始数据、位深和二维约束

V1 接受单张二维 PNG/JPEG/TIFF；JPEG 可用于形态演示，定量分析优先使用原始无损 TIFF。
TIFF 通过科学图像读取库读取数值数组及元数据；tifffile 是候选，具体版本和依赖需锁定。[tifffile 官方仓库](https://github.com/cgohlke/tifffile)
保留 uint8、uint16 或支持的浮点类型，不把 16 位原图转换为 8 位后再测强度或重写原文件。
显示窗宽窗位、亮度和伪彩色只影响预览，不修改原始测量数据。
分割可有标准化副本，必须记录标准化参数；尺寸在映射回原坐标后的掩膜上计算。
多页 TIFF、Z-stack、时间序列和全切片首版明确拒绝，提示结构和原因；不能悄悄取第一页。
二维多通道 TIFF 必须明确识别通道轴；无法区分通道轴和 Z 轴时要求选择正确输入，不能猜。
初始限额建议文件 100MB、二维图像 4096×4096；先检查解码后数组内存，再决定接受。
大图、异常压缩和损坏标签均要安全失败；不一次性把整个文件夹的原图读入内存。
原图默认按项目长期保存，用户主动删除前显示对分析结果的影响；不套用普通临时素材的自动清理规则。

## 4. 算法与模型：先建立可发布基线

默认基线为阈值、距离变换、标记分水岭与确定性测量，仅用于经过验证的清晰核图。
它无需下载大型权重，CPU 可运行；分水岭可根据标记分离相接对象，真实图效果仍需验收。[scikit-image 分水岭示例](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_watershed.html)
该基线不能替代通用细胞分割；对高密度、弱边界或复杂胞质不达标时，应收窄范围或暂不开放自动功能。

| 路线 | 用途 | 当前发布决策 |
| --- | --- | --- |
| 阈值＋分水岭 | 清晰二维核图的 CPU 基线、用户可调标记 | 验收通过且依赖许可完整后可作为默认 |
| Cellpose 3.1.1.1 `nuclei` | 核图的低资源研究评测候选 | 固定版本独立适配；具体权重分发条件核清前不进默认包 |
| Cellpose 3.1.1.1 `cyto3` | 有明确胞质边界/通道的细胞图候选 | 另建预设和验证集，不能套核图指标 |
| Cellpose 4 系列 | 困难样本上的后续对照 | 先验资源、依赖和许可，再决定是否需要 |
| 手动画掩膜 | 模型缺失、自动分割失败或需精修 | 总是可用，结果标注人工来源 |

Cellpose 3 文档区分 `nuclei` 和 `cyto3`，且通道设置依模型而异；不要把不同版本的调用接口混用。[Cellpose 3 模型文档](https://cellpose.readthedocs.io/en/v3.1.1.1/models.html)
当前 Cellpose 4 文档已有 `cpsam_v2`、`cpdino`、较小的 `cpdino-vitb` 等候选，不能再把“安装最新版 Cellpose”当作固定的轻量路线。[当前模型文档](https://cellpose.readthedocs.io/en/latest/models.html)
对 8GB 显存/16GB 内存，首先测试一张 1024×1024 图、batch=1、显式对象直径和受控分块。
CPU 回退是待测试能力，不保证所有图像可接受速度；RTX 5060 的运行时兼容性随锁定的 PyTorch/CUDA 包做安装验证。
不随应用运行自动执行 pip upgrade；最终冻结 sidecar 环境、权重校验值和适配器版本。

许可核查必须分层：

- Cellpose 代码仓库标 BSD-3-Clause；这不自动覆盖所有预训练权重、训练图像与示例素材。[代码许可](https://github.com/MouseLand/cellpose/blob/main/LICENSE)
- 当前官方 README 说明所有 Cellpose 模型使用 CC-BY-NC 数据训练；不能把这句话直接解释成权重必然采用相同许可。[官方 README](https://github.com/MouseLand/cellpose)
- 官方 cellpose-sam 权重仓库元数据标 BSD-3-Clause，但卡正文为空；发布前仍需核对所用文件、版本、上游声明与分发条件。[权重仓库](https://huggingface.co/mouseland/cellpose-sam)
- 本规划的保守工程决策是：上述权重授权范围未形成明确记录前，商店默认包仅含已核清的算法与组件；研究评测与商店发布分开。
- scikit-image 及其依赖同样整理版权通知和第三方组件清单，不能因无需模型权重就跳过依赖许可。[scikit-image 许可文件](https://github.com/scikit-image/scikit-image/blob/main/LICENSE.txt)

## 5. 计算口径与可复现测量

若横纵像素间距分别为 `sx, sy`（μm/px），掩膜包含 N 个原图像素：

```text
面积 A = N × sx × sy
等效直径 d = 2 × sqrt(A / π)
无尺度：面积为 px²，等效直径为 px
有效数量 = 筛选规则作用后的实例数
规则异常比例 = 异常且有效的实例数 / 有效实例总数
```

仅有“40× 放大倍数”不能给出准确尺度；允许用户输入 sx、sy 或用可靠标尺校准。
手动画单条标尺只在方形像素假设已确认时同时确定 sx、sy；非等距像素需分别校准或取得可靠元数据。
存在元数据与人工尺度冲突时显示两者，要求选择并记录理由；不能无声覆盖。
长短轴应在物理坐标下计算，尤其 sx≠sy 时不能把像素长轴乘一个平均比例系数。
裁剪、缩放、分块必须保存坐标变换；展示缩略图不能作为真实测量输入。
对象跨分块边界时采用重叠、统一 ID 和合并规则；至少用跨缝实例验证无重复计数与错误裁断。
首版强度统计默认关闭，待曝光、背景扣除、原始位深与通道口径验证后单独加入。

异常 V1 仅支持用户定义的形态规则，如面积低于阈值或偏心率超限，名称为“规则标记异常”。
没有配置规则时显示“未配置”，不是 0%；有效对象为 0 时比例为 N/A，不是 0%。
排除边缘对象、碎片和用户删除对象的规则同时作用于分子与分母；报告各类排除数量。
多个异常规则命中同一实例时，整体异常数按实例去重，逐规则统计另列并说明可重叠。
生物学异常分类需要独立分类标签与判定标准，不从形态阈值直接升级为病理结论。

## 6. 数据实体、接口和导出

| 实体 | 关键内容 |
| --- | --- |
| LabProject / Specimen | 项目、实验批次、样本代号、成像方式、对象定义 |
| ImageAcquisition | 原图素材、位深、维度/通道、哈希、采集元数据 |
| Calibration | sx/sy、单位、来源、标尺端点、确认人、版本 |
| AnalysisRun | 输入与模型版本、参数、阈值、通道、分块与坐标变换 |
| ObjectMeasurement | 稳定对象 ID、掩膜引用、面积、轴长、有效性、排除原因 |
| RuleSet | 异常规则、筛选规则、单位、版本、分母口径 |
| Revision / Review | 编辑事件、旧/新版本、对象继承映射、复核人、时间 |

逻辑能力：`lab.inspect、lab.calibrate、lab.segment、lab.revise、lab.measure、lab.export`。
桌面 Rust 层负责项目权限、受控文件访问与 SQLite 单写入；模型和测量在打包 Python sidecar 中执行。
JSONL 消息传素材引用、参数和结果摘要；大数组写受控输出文件，不用 Base64 塞入消息。
每次测量必须引用确定的掩膜、尺度和规则版本；改变任一项都生成新测量版本。
参数 schema 带版本；旧项目能读取，不因模型更新而自动重算或丢失单位。

导出包包括原图引用/可选副本、整数实例标签 TIFF、叠加预览、逐对象 CSV、汇总 JSON、修订记录和说明。
标签图是整数实例 ID，不是彩色 JPEG；保存足够位深，避免对象数超过 65535 时溢出。
CSV 逐列写明单位；summary 包含原始数量、有效数量、排除数量、异常分子/分母及 N/A 原因。
报告区分自动分割结果与复核后结果；复核只证明有人检查，不能标为算法原始准确率。
用户导出的文件属于独立副本，软件删除项目不能承诺连同外部导出文件一起销毁。

## 7. 免费视觉 API 与服务端边界

允许在用户明确启用后，把脱敏的图例或已导出的汇总文本交给免费 API 辅助解释字段、组织报告。
默认优先本地固定报告模板；没有网络和额度仍能完成测量与导出。
API 不能返回替代掩膜的“目测计数”，也不能凭图片生成尺度、尺寸、细胞名称或异常比例。
未公开实验图和涉及个人信息的样本不默认外发；外发范围、供应商和用途在操作前清楚展示。
报告改写必须保持数值、单位和 N/A 字段不变，生成后对照原 JSON 校验。
4 核/2GB 辅助服务器不运行分割模型、不接收原始 TIFF 作为默认流程，也不充当显存扩展。

## 8. 验收数据、异常恢复与资源

至少准备同一成像类型 30 张独立人工标注盲测图，包含稀疏、密集、低质量与空白场景；开发调参图另备。
按样本/培养批次/采集批次切分，不能把同一视野裁块分到开发集和测试集。
标注规则明确相接对象、截边对象和碎片的处理；至少双人复核争议对象并记录一致性。
冻结参数后再开盲测；标注数量不足时先报告可行性，不宣传达到稳定泛化。

| 验收项 | 初始目标与必要说明 |
| --- | --- |
| 数量误差 | 非空图平均相对计数误差 ≤10%；同时报告 MAE、逐图误差及真实计数 |
| 实例质量 | IoU≥0.5 的一对一匹配，精确率/召回率各 ≥0.85；同时报告重叠指标 |
| 空白图 | 单独报告误检，不在相对误差中用除以零或跳过后不披露 |
| 科学口径 | 已知合成掩膜的面积/尺度换算、非等距轴长、空分母、规则去重通过 |
| 人工操作 | 增删拆合、撤销重做、重启恢复、版本导出和对象表高亮一致 |
| 数据完整性 | 16 位 TIFF 原值保留；多页拒绝；原图未覆盖；标签 ID 无溢出 |
| 资源 | 30 图记录 P50/P95、峰值 RAM/VRAM；核图 1024² 热处理 P95 ≤30 秒为候选目标 |

目标只在冻结的成像域有效；计数误差达标但分割精召不达标不能通过，因为过分割与漏分割可能抵消。
GPU 串行共享；显存不足时缩小分块或尝试已验证 CPU 路线，并保存失败参数，禁止无限重试。
中途取消、sidecar 崩溃、磁盘不足时保留原图和已有修订；不保存伪成功测量。
导出先写临时文件，校验清单后原子完成；失败返回可重试状态，已存在文件不静默覆盖。

## 9. 分阶段实施、成本与上线门槛

以下是公共桌面框架完成后的单开发者全职增量，不含专业标注排期。

| 阶段 | 参考工期 | 交付 |
| --- | --- | --- |
| L0 场景与口径 | 2–3 天 | 代表样本、对象定义、尺度方案、标注规范和许可台账 |
| L1 算法验证 | 3–5 天 | 阈值/分水岭基线、Cellpose 可选对照、资源与失败样例 |
| L2 桌面复核 | 5–7 天 | 图像画布、通道/尺度、对象表、增删拆合和版本保存 |
| L3 测量导出 | 3–4 天 | 统计口径、规则、CSV/JSON/掩膜包和科学一致性检查 |
| L4 盲测打包 | 3–4 天 | 固定盲测报告、离线安装、异常恢复、依赖许可与发布清单 |

V1 预计 3–5 周；复杂批处理、细胞分类或新成像域单独估算，不能塞进首版工期。
现有硬件足够先验证传统算法；是否能稳定运行某个模型由实测决定，不先租 GPU。
主要成本是专业标注与复核、原始 TIFF 存储和维护；压缩无损原图可以研究，但不靠有损降位深省空间。
商店开放条件：范围可解释、单位与分母正确、盲测达标、人工修订可追溯、所有实际分发资产许可明确。
自动分割未达标时，可先发布校准、人工标注、测量和导出工具；该模式明确标记人工处理，不能宣传为自动细胞识别。
