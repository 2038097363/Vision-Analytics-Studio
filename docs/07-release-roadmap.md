# 安装、软件商店发布与实施路线图

> 规划日期：2026-09-14。默认首发 Windows 11 x64，目标 Microsoft Store；不代表已经创建开发者账号、完成签名、打包或获得审核。商店政策与费用在提交时重新核验。

## 1. 三个交付层级

| 层级 | 给谁使用 | 能证明什么 |
| --- | --- | --- |
| 研究原型 | 开发者和获得适用授权的研究测试者 | 模型可行性与输入范围；不能据此宣称可公开分发 |
| 桌面内测版 | 小范围 Windows 用户 | 安装、任务、异常恢复、硬件兼容与实际体验 |
| 商店发行版 | 公开用户 | 只有分发权、真实能力、安装与产品完整性均满足的功能才上线 |

研究环境能跑的模型未必可以进入商店包。免费分发软件也不自动满足“仅研究／评估”的模型许可。发行清单应准确记录开启的模块与模型，不把禁用的研究能力写进商店截图和介绍。

目标仍是四个模块逐步可交付；首个内测以相册基础和单件试衣为主。如果试衣许可或质量暂时未通过，继续解决该门槛，或单独发布功能说明准确的基础工具版本；不能把后者当成四模块完整目标已完成。

## 2. Windows 分发路线比较

| 路线 | 需要做什么 | 成本与取舍 |
| --- | --- | --- |
| Microsoft Store 的 MSIX | 额外打包为 MSIX、设置身份与能力、提交验证 | 优先验证；商店可提供包托管、签名与更新，减少自建分发基础设施 |
| Microsoft Store 的 EXE/MSI 链接 | 完整离线安装器、可信代码签名、稳定版本下载地址、静默安装 | Tauri 官方指南覆盖此路；需核算证书与托管，不能默认零成本 |
| 直接发安装器内测 | 构建与安装测试，说明发布者和版本 | 适合受控测试；未签名包可能有信任提示，不能要求用户关闭系统保护 |

Microsoft 官方提供 MSIX 包装和商店签名说明；通过商店分发的 MSIX 与在商店外侧载自签名包不是一回事。[MSIX 创建工具](https://learn.microsoft.com/en-us/windows/msix/packaging-tool/create-app-package)、[MSIX 签名说明](https://learn.microsoft.com/en-us/windows/msix/package/signing-package-overview)

**Tauri 当前官方打包器直接生成 EXE/MSI，不直接生成 MSIX。** 本项目若走 MSIX，必须增加 Windows 打包工具链验证，不能写成“一条 Tauri 命令直接上架 MSIX”。官方 EXE/MSI 商店路线要求相应的离线 WebView2 安装配置、代码签名等准备。[Tauri Microsoft Store 指南](https://v2.tauri.app/distribute/microsoft-store/)

第一阶段先把最小应用、Python sidecar 和数据目录放进一个 MSIX 测试包，验证启动、进程、文件访问、WebView2、GPU 库加载及升级。如果这一验证失败，比较修复成本与 EXE/MSI 签名成本，再选单一路线；不拖到全项目完成后才决策。

Microsoft 已提供个人开发者免费注册路径及相应商店分发支持，但需要完成身份验证并符合可用地区条件；开发者资格、费用与实际开户结果以当前官方页面为准。本轮不替用户申请账号或购买证书。[开发者注册](https://learn.microsoft.com/en-us/windows/apps/publish/faq/open-developer-account)、[Microsoft 官方免费注册说明](https://blogs.windows.com/windowsdeveloper/2025/09/10/free-developer-registration-for-individual-developers-on-microsoft-store/)

## 3. 安装与模型分发设计

安装软件本体时完成可离线使用的基础界面、素材管理和必要程序组件。用户无需自行装开发工具，也不会看到自动 pip install 的终端。正式程序日常运行不要求管理员权限。

WebView2 缺失时按选定分发方式提供可测试的运行时部署流程。在线与离线安装方案分开测试；依赖安装器的体积计入总下载量，而不是只展示应用壳大小。

大型模型权重首次使用时由模型中心提示下载，也支持匹配清单的离线导入。程序二进制／DLL 与纯数据权重分开管理：发行版程序更新走选定的软件更新通道；模型数据更新校验许可、哈希与适配器兼容性，不执行下载来的任意脚本。

公开包内不放非商业研究候选的权重，不把其下载入口当成默认激活通道。许可证、依赖声明和模型用途以实际发布清单为准；第三方权重 URL 是否允许直接面向所有用户下载也要确认，避免消耗不允许的公共带宽。

模型更新先下载新版本、校验、运行小型授权样例，再切换活动版本；失败回到上一版。清理旧权重前显示占用和影响，保留用户回退机会。

## 4. 更新、退出与卸载

商店 MSIX 版本使用商店更新通道，不再叠加一个修改程序文件的自更新器。若走 EXE/MSI，则单独实现签名校验、版本下载和更新回退；不能让两套更新通道争抢同一安装目录。

有模型任务运行时先完成或明确停止任务，再更新程序。数据库迁移前备份，新增 schema 向旧数据兼容；迁移失败保持原数据可恢复，不启动半迁移状态。

退出应用要回收 Python 子进程、临时文件与锁；用户主动选择托盘模式时才继续计算。睡眠、断电和系统重启后把中断任务标成可恢复重试，不伪装成后台仍在计算。

卸载前在软件设置中提供“导出数据／清理模型缓存／清理工作区”。安装渠道对应用数据的卸载行为要实测并披露；用户保存在应用管理目录之外的原图与导出文件不能自动删除。

## 5. 上架前应准备的材料

- 软件名称、唯一应用身份、发布者名称、图标、多尺寸资源和实际截图。
- 准确的功能说明：哪些离线、哪些需 NVIDIA GPU、哪些需额外下载、哪些免费 API 是可选项。
- 本地与网络数据说明：处理位置、第三方服务、退出／撤销／删除方式、联系渠道和隐私政策 URL。
- 版权与模型清单：代码、权重、基础模型、解析器、字体、图标、示例图片各自来源和许可。
- 可审查的真实操作路径与授权示例；若必须登录则提供审核可用账户，若依赖服务则保持该服务可用。
- 无合适 GPU 的明确行为：基础管理可以用，试衣功能显示实际条件，不无限加载。
- 年龄分级与生成内容说明；不宣传真实尺码预测、医疗诊断或超出评测范围的识别能力。

上述材料源于项目实际能力与分发要求；具体审核以官方政策为准，提交时再次检查，不能保证“用了某框架就一定过审”。[Microsoft Store 政策](https://learn.microsoft.com/en-us/windows/apps/publish/store-policies)

## 6. 安装与发行验证矩阵

| 环境／事件 | 必须验证 |
| --- | --- |
| 干净 Windows 11 x64 | 无 Python/Node/Git 时安装、首次启动、基本素材管理 |
| 当前 RTX 5060 Laptop | 选定驱动与推理包组合真实运行，记录 GPU 型号、RAM 与峰值显存 |
| 无独显电脑 | 不加载 CUDA 路线，CPU 基础功能可用，界面不崩溃 |
| 普通用户权限 | 读写应用数据目录、选定外部目录、导出和 sidecar 启动 |
| 高 DPI／中文长路径 | 文字不截断、对话框正常、路径无需英文重命名 |
| 断网／低磁盘 | 基础功能可用；下载暂停／失败明确，不留下伪完整模型 |
| 中断与重启 | 任务和导入可恢复，结果不串工作区，取消状态一致 |
| 升级与卸载 | 数据库备份迁移、版本回退、用户数据去向明确 |
| 免费 API 不可用 | 限流、到期、地区限制、改价、超时均不触发付费兜底 |
| 账户服务停机 | 本地功能正常；云操作说明状态，不把离线缓存身份当在线授权 |

虚拟机适合安装和 CPU 检查，但不能替代真实 GPU 兼容测试。最终还需至少一台独立于开发环境的电脑；只有一台时在报告中明确覆盖不足。

## 7. 总体开发顺序与估算

按 1 名熟悉 Web/Python、需要补充少量桌面工程经验的开发者全职估算；专业标注、取得授权和商店审核等待另计。各模块文档列的是增量任务，不重复计算公共素材、任务和画布建设。

| 阶段 | 参考周次 | 可交付结果 | 下一阶段门槛 |
| --- | --- | --- | --- |
| S0 技术与打包验证 | 第 1–2 周 | 本机试衣候选、桌面窗口、打包 sidecar、最小 MSIX 试验 | 资源与发行路线有依据；未通过则先解决，不先建完整 UI |
| S1 公共桌面基础 | 第 3–4 周 | 首次启动、首页、设备相册授权与索引、导入、任务、设置和模型中心 | 干净机基础运行、重启恢复与目录权限边界通过 |
| S2 虚拟穿搭 MVP | 第 5–8 周 | 双图、检查、生成、对比、反馈、固定评测 | 核心质量达标；研究与可发行模型状态分开 |
| S3 相册完善 | 第 9–10 周 | 本地安全分类、分类页、未分类图库、搜索、去重提示、回收站 | 无 GPU 仍可手动整理；不生成敏感标签；删除不影响外部原文件 |
| S4 植物工作区 | 第 11–13 周 | 有限物种识别、资料与观察档案 | 未知类拒答、授权实拍评测与资料核对完成 |
| S5 实验室工作区 | 第 14–17 周 | 指定核图分割、校准、人工复核、统计和导出 | 科学口径与独立标注评测通过 |
| S6 发布整理 | 第 18–19 周 | 干净机验证、升级卸载、依赖清单、商店资料 | 发布清单中每项能力与真实发行包一致 |

总基线约 19 周，再预留 3–5 周兼容性和质量返工，即 **约 22–24 周**；这比之前的网页初版估算增加了桌面打包、完整交互、分发和科学复核工作。首个可内测的桌面试衣版本争取第 8 周左右，不等待全部模块完成才试用。

正式发行前置增量：真实云注册登录、验证／恢复、会话轮换与限流约 1.5–2 周；云端元数据同步、注销删除和备份恢复约 1 周。首个免费视觉 API 适配与预算控制约 0.5–1 周；配对远程 Worker 和图片中转约 1–2 周。图片对象同步、手机端、商业模型授权和大规模训练另立项。

## 9. 零预算阶段的取舍

先使用现有电脑和免费开源开发工具，不租 GPU、不预购短信、不自建云图库、不提供无限公共免费 API。封闭开发期可不租服务器；开始账户联调时再租 4 核／2GB 实例，图片原件继续默认留在设备，对象存储只随用户同步需求启用。

免费开发者注册不等于整套产品发布零成本：数据授权、专业标注、额外设备测试、代码签名路线、下载带宽和长期维护都要单独核算。优先让预算用在导致目标无法完成的实际问题上，而不是提前堆服务器。

整个规划的完成标准是能按文件逐项实施并验证；本轮仅交付这些规划，不声称软件、注册服务或商店发布已完成。
