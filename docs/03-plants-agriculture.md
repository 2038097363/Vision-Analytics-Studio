# 植物与农业模块规划

> 状态：工程闭环已完成，质量评测待做；更新于 2026-09-19。本文未标成实测的数据仍是规划目标。
> 交付对象：Windows 桌面软件中的独立工作区，共享主程序的素材、模型、任务和本地资料库。

公共约定见 [整体框架](00-overall-architecture.md)，免费服务和预算边界见 [模型与成本](06-models-and-cost.md)。

## 当前实现进度（2026-09-19）

已完成可运行的植物观察工作区：图片导入与本地预览、整株／叶／花／果输入、备注、固定 20 种 Top-3 候选、人工确认或“暂不确认”、观察历史、任务记录、SQLite 持久化和重启恢复。图片分析默认不联网，不读取 EXIF 定位，也不会把图片上传账户服务器。

本地引擎使用 BioCLIP ViT-B/16 与 OpenCLIP 3.3.0，固定模型提交 `ce901ab3c6a913f9e9ef94ce6d27761069f4f01c`。权重为 598,599,013 字节，SHA-256 为 `e380384f0c30d425d8c6c40f24471f9dd497fbdfa734a89c461a94aee95f0ef4`；清单见 `models/plants/manifest.json`，环境安装入口见 `scripts/setup-plant-evaluation.ps1`。

当前电脑已完成真实 CUDA 加载和桌面端到端调用，抽象测试图的冷启动识别约 10.3 秒。该图片不是评测样本，因此只能证明运行链路成立。当前所有结果保持 `uncertain`，界面把分数称为“范围内相似分”；在授权实拍数据、范围外数据和阈值校准完成前，不开放自动确认和确定性物种结论。

尚未完成：200 张独立盲测、未知类拒答阈值、物种资料卡与来源台账、裁剪与同株多图、导出、删除入口和发布包内的 Python sidecar。病虫害、食用性、毒性、药用价值与农艺建议仍不在首版自动识别范围内。

## 1. 用户与首版价值

首先服务植物爱好者：把手机拍摄的植物照片传到电脑，获得有限范围内的候选识别、资料卡和观察记录。
农业用户先获得可见状态记录；只有取得指定作物数据并通过独立评测后，才增加病虫害辅助识别。
用户不需要懂模型参数；最短路径是“导入一张图 → 查看候选 → 补充确认 → 保存观察”。
首发是电脑软件；电脑上离线识别不等于手机端离线识别，户外现场使用不是 V1 承诺。

| 版本 | 可交付能力 | 开放条件 |
| --- | --- | --- |
| V1 | 一个地区约 20–50 种植物，Top-3 候选、资料卡、状态记录、补拍建议 | 先冻结 20 种起步；盲测达标后扩充 |
| V1.1 | 同株多图、观察时间线、相册联动、相似资料检索 | 单图流程和数据结构稳定 |
| V2 | 单一作物、少数明确病害类别和生长阶段 | 取得目标域标注和农业人员复核 |
| 暂不承诺 | 全球物种覆盖、单图确定诊断、农药剂量、产量预测 | 另立专项，不写进商店首发介绍 |

软件输出“识别候选”，不把食用、毒性、药用判断交给图片识别结果。
缺少关键部位时允许停在属、科或“暂不能可靠识别”，不强制给出物种名。

## 2. 桌面交互与页面

模块入口展示“新建观察、最近观察、支持物种、离线资料状态”四项。
工作区采用左侧观察列表、中间大图、右侧结果卡；所有列表支持键盘操作与缩放。

| 区域 | 操作和反馈 |
| --- | --- |
| 导入区 | 系统文件选择器、拖入文件、从个人相册选择；提示 JPEG/PNG/WebP 支持情况 |
| 图片区 | 缩放、旋转、选择主体裁剪区域；保留原图和裁剪坐标 |
| 补充信息 | 整株/叶/花/果、拍摄日期、可选地区、用户备注；位置默认空白 |
| 分析设置 | 默认“本地识别”；可选“补充可见特征描述”；展示预计下载量和设备可用性 |
| 候选卡 | 中文名、学名、排名、可见支持特征、欠缺证据、资料来源、人工确认入口 |
| 观察记录 | 未确认/用户确认/已修正；保存同株档案和复查备注 |
| 空与失败状态 | 给出拍摄示例、离线资料缺失、模型未安装、主体不明、范围外和任务失败提示 |

正式版首次使用先完成联网注册或登录；植物档案归属当前云账户并保留设备缓存。登录不会自动上传照片，图片同步或云分析仍需用户单独开启。
关闭模块或切到相册时任务继续排队；关闭软件遵循整体框架的退出与取消规则。
免费视觉 API 在用户启用后才显示网络补充按钮，默认主按钮仍为本地识别。
两条路线的结果分开展示来源，API 结果不覆盖用户已确认的名字。

## 3. 输入、输出与支持边界

V1 输入一张静态图，建议主体占画面主要部分且纹理可辨认；多植物混杂时引导先裁剪。
设置文件体积、像素总量和解码内存上限；初始候选为 25MB、2400 万像素，压测后冻结。
EXIF 朝向只影响显示和分析副本；原图保留，定位不写入外发副本。
低分辨率不是统一拒绝条件，应结合模糊、主体大小和缺失部位生成具体提示。
照片中的文字是输入数据，不能触发系统命令、修改模型策略或自动打开链接。

输出包含：`candidates[]、decision、visible_features[]、missing_evidence[]、observation_tags[]、sources[]`。
`decision` 为 `candidate / uncertain / unsupported / input_invalid`；未识别不等于系统错误。
候选分数保留在评测数据中，未经过校准不在界面标成“识别准确率 98%”。
资料卡与当前图片证据分开：物种通常特征来自资料；照片可见特征来自本次观察。
只启用 BioCLIP 检索而未启用描述模型时，不从候选名称反推“照片上看见了某特征”；`visible_features` 可以为空或只含用户确认的观察。手动状态记录与自动描述清楚区分来源。
导出 Markdown/JSON 观察报告及带来源标记的预览图；CSV 用于批量观察清单。
导出文件注明识别引擎版本、支持范围版本、用户修正状态和生成时间。

## 4. 低成本本地算法路线

默认先评测 BioCLIP 初代 ViT-B/16 的有限候选检索，不先训练分类器，也不先加载大型视觉语言模型。
官方模型卡给出了该架构和 MIT 许可，支持零样本和少样本物种分类；本项目的低资源适配是待验证选择，并非官方对本机速度的承诺。[BioCLIP 模型卡](https://huggingface.co/imageomics/bioclip)

| 角色 | 默认/候选 | 决策标准 |
| --- | --- | --- |
| 图片与物种匹配 | BioCLIP ViT-B/16 + 固定物种学名/英文名模板 | 先 CPU、再 GPU 对比；精度与资源同时达标 |
| 少样本补强 | 同一编码器 + 经授权参考图原型/kNN | 只有独立盲测改善才上线，不能拿测试图建索引 |
| 中文可见特征描述 | 可选 Qwen3-VL-2B-Instruct | 共享相册描述引擎，单图短输出，不作为分类真值 |
| 无模型后备 | 本地资料搜索 + 用户确认 + 观察记录 | 保证离线仍可使用；不伪装为自动识别 |

Qwen3-VL-2B-Instruct 的官方卡标注 Apache-2.0；只列为额外描述候选。量化来源、视觉组件支持及 8GB 显存/16GB 内存下的运行峰值需要另测。[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)
不默认安装 4B 和 2B 两份模型；若共享的 2B 描述模型已经安装就复用，无需求可不安装。
BioCLIP 的文本输入按其语言能力使用学名/英文模板，中文展示通过经过校对的名称表映射。
图库参考图的背景、摄影风格与采集季节不能全部一致，否则模型容易按背景而非植物分类。

处理步骤：

1. 校验输入，建立原图引用和方向正确的分析副本。
2. 做模糊、曝光、主体大小检查；用户确认主体区域。
3. 编码图片，与固定支持类及近邻混淆类进行相似度比较。
4. 使用验证集选定的分数阈值、候选间距和输入质量规则，决定给候选还是拒答。
5. 查询本地资料表；仅在可选描述开启时调用本地小型视觉语言模型。
6. 校验输出字段，禁止生成资料表中不存在的引用；未观察到的特征不能作为支持证据。
7. 保存识别版本，等待用户确认；人工纠正作为反馈记录，不自动进入训练库。

仅在 20 个类别中归一化的最高分不能证明图片属于这 20 类。
未知类需要真实范围外植物、动物、塑料花、食物和非植物图片进行测试；阈值拒答只能减少误认，不能保证识别所有未知类。
模型之间意见一致也不是新的真实证据；照片信息不足时仍然返回补拍建议。

## 5. 病虫害、生长阶段与资料来源

V1 只记录可见现象，如叶片发黄、叶面斑点、孔洞、卷曲、开花、结果；“未见异常”不等于健康诊断。
V2 先选一个作物、一个采集场景和 3–5 个互斥或明确多标签类别，必须额外含未知/混合原因。
病害判断需要全株图与局部图、作物品种、症状位置、发生时间等上下文；单图不足则不推定病因。
阴影、失焦、缺水、营养问题、机械伤害可能相似；输出可见证据与待排查项，不自动给确定用药方案。
生长阶段使用作物专属定义；先由用户填播种日期和观察阶段，自动建议只覆盖验证过的可见阶段。
照片看不到的根系、生理状态和内部病变保持未知；不能根据连续照片自动推断真实产量。

植物名称及资料优先核对植物园、植物志、科研机构和农业推广机构的公开资料。
例如 Kew 的 Plants of the World Online 可作为学名与分类资料核对入口；本地内容复用范围仍须核对其条款。[Kew POWO 项目说明](https://powo.science.kew.org/about)
首版自己编写简短资料摘要并保留来源链接；没有获得复制许可的整段文字与图片不打包进应用。
字段至少包括 `taxon_id、accepted_name、synonyms、chinese_name、region、source_url、retrieved_at、license、reviewer`。
模型生成描述不成为百科条目的权威来源，资料缺失直接显示“暂无已整理资料”。

## 6. 免费 API 的限定用途

沿用整体免费 API 方案中的可用供应商清单；额度、地域、隐私政策以启用时核验结果为准。
可辅助：中文图片描述、候选特征对照、把本地资料改写成易读说明。
不可替代：未知类验收、作物病害专用验证、实验测量或农艺决策。
首次外发前展示将发送的图片副本、接收方和目的；允许只发送裁剪图与去定位副本。
用户自带 Key 时存入系统凭据保护区；开发者不把共享 Key 写入安装包。
设单图一次请求、输出长度上限和每日次数上限；可取消，429/额度耗尽时回到本地流程。
禁止自动切换收费档位；不能把免费的网页聊天界面作为批量 API 或用浏览器驱动绕过额度。
保存来源、模型名、请求时间及用量；不在日志保留图片正文或完整密钥。

## 7. 数据实体与模块接口

| 实体 | 关键字段 |
| --- | --- |
| PlantTaxon | 支持范围版本、分类名、别名、资料版本、许可状态 |
| PlantSpecimen | 本地归属、用户命名、确认物种、可选地区、创建日期 |
| PlantObservation | 植株 ID、素材 ID、拍摄时间、部位、备注、确认状态 |
| PlantPrediction | 任务 ID、候选列表、拒答原因、证据、模型和阈值版本 |
| PlantCorrection | 修改前后值、操作者、时间、理由、关联预测版本 |
| SourceRecord | 来源地址、作者、读取日期、摘要、使用许可 |

逻辑能力：`plant.inspect_input、plant.identify、plant.describe、plant.confirm、plant.export`。
桌面壳验证素材权限和参数，通过统一任务调度调用 Python sidecar；消息使用 JSONL，图像走受控文件引用。
Python 仅返回结果与文件清单；持久化由主程序统一写入 SQLite，不产生第二套账号与数据库。
结果结构带 `schema_version`；标签采用固定枚举＋原始描述，避免名称变化破坏历史检索。
资料升级与模型升级不自动重写历史结果；用户主动重分析产生新版本。

## 8. 数据准备与验收门槛

先冻结地区及 20 种清单，每类收集多植株、不同背景、叶花果与手机来源的授权照片。
至少 200 张独立实拍盲测图，其中建议范围内 150 张、未知/非植物 50 张；这只是初步门槛，不足以证明全国泛化。
开发、阈值选择与最终盲测按植株及拍摄来源分组；连拍、裁剪和增强版本必须留在同一组。
扩到 50 类时应同步增加每类样本，不以原来的 200 张平均摊薄后继续宣称同样可靠。
少样本原型库、规则调参集、最终测试集分离；资料示例图也不能偷偷成为测试参考图。

| 验收项 | 初始目标与报告方式 |
| --- | --- |
| 已知类命中 | 全部已知测试图 Top-3 ≥85%；同时报告 Top-1 与逐类结果 |
| 未知类 | 高确定性误认率 ≤10%；记录阈值与被拒答的真实样例 |
| 拒答质量 | 同时报覆盖率、拒答率、保留结果准确率；不能只测“答对时准确率” |
| 可见特征 | 至少 50 图人工审查，每个输出特征能在图上核实；错误特征单独统计 |
| 资料质量 | 已开放物种的名称与资料来源完整率 100%，失效链接有缓存摘要及核对记录 |
| 操作闭环 | 导入、候选、修正、保存、重启恢复、导出、删除均可完成 |
| 离线运行 | 预装模型资料后断网运行；未启用 API 时无隐式外发 |

单图性能先用 30 张标准图记录 CPU/GPU 冷启动、热运行 P50/P95、峰值内存和显存。
候选目标为本地识别热运行 P95 ≤10 秒、附加描述 ≤30 秒；以本机实测决定是否保留功能。
同时运行试衣时识别排队，不能通过加载第二套 GPU 模型争抢 8GB 显存。
显存不足可降为 CPU 检索或保留手动资料记录；对描述功能单独禁用，不删除已有观察。

## 9. 实施工期、成本与发布风险

以下为公共桌面框架已具备后，单开发者全职增量工期；数据采集与专家复核时间另计。

| 阶段 | 参考工期 | 交付与通过条件 |
| --- | --- | --- |
| P0 范围与数据 | 2–3 天 | 20 类清单、许可台账、开发/验证/盲测划分 |
| P1 本地基线 | 3–4 天 | BioCLIP 检索、未知类拒答基线、资源测试报告 |
| P2 桌面闭环 | 4–5 天 | 导入、候选卡、资料卡、手动确认和观察记录 |
| P3 质量与打包 | 3–4 天 | 独立验收、异常恢复、离线安装/运行与导出 |
| 后续增量 | 各 1–2 周起 | 多图或单作物试点，分别评测后开放 |

V1 预计约 2.5–3.5 周；若没有足够授权实拍图，先交付明确标识的限定样例演示。
常规使用无按次推理费；主要成本是资料整理、标注、磁盘、模型下载流量和本机电费。
4 核/2GB 服务器仅可选用于账户、版本清单和少量元数据；不承载植物模型或长期原图图库。
模型和资料按需下载，下载前显示体积；低预算模式不安装描述模型、不启用云端。
BioCLIP 代码、具体权重、OpenCLIP 依赖、参考图和资料文本逐项登记许可，不用代码许可替代图片授权。
官方模型卡另有鼓励衍生项目开源的表述；发布前保留并复核完整许可及通知，不能只看仓库标签。
数据域偏移、资料更新和误识别是长期维护重点；每次扩大地区/类别都新增评测版本。
发布验收失败时保留观察与资料功能，把自动识别标为实验功能或暂不开放。
