# 下一阶段升级清单

> 更新：2026-09-20。排序依据是能否交付给真实用户、是否保护图片数据、是否能在低预算下稳定运行。

## P0：把当前可运行版本变成可安装版本

当前程序已经能在开发目录中启动，但发布 EXE 仍依赖项目内的 Python 源码、运行时和模型目录。下一步应把 Python 引擎制作为 Tauri sidecar，把必要资源纳入安装包，并完成无开发环境电脑上的干净安装、升级和卸载测试。

验收条件：

- 用户双击安装包即可安装，不需要 Node.js、Rust 或系统 Python。
- 首次启动能检测 GPU、磁盘空间和 WebView2；缺失组件有明确处理入口。
- 模型按需下载，下载可暂停、校验、续传和删除，不把约 2.6GB 权重塞进首包。
- 安装、升级和卸载都不误删用户原图；卸载时由用户选择是否保留应用数据。
- 先完成签名 EXE/MSI 内测，再评估 MSIX 和 Microsoft Store 提交。

## P0：账户、数据库与图片安全闭环

账户 API 和 PostgreSQL 结构已经存在，但桌面端正式版还需要把登录会话保存在 Windows Credential Manager，并建立设备会话撤销、异常登录提示和令牌轮换。图片默认只留在设备；未来同步时，PostgreSQL 只存元数据和对象键，图片进入对象存储并按用户隔离。

验收条件：

- 正式模式必须登录；开发模式有清楚标识，不能被打包进商店版本。
- 访问令牌只在内存中，刷新令牌进入系统凭据库；日志、任务参数和崩溃报告不含令牌、原图路径或图片内容。
- 图片同步默认关闭，按相册或单张显式授权；删除账户能撤销会话并排队删除云端数据。
- 服务端对图片使用短时签名地址、用户级访问检查、静态加密、上传类型与大小校验。
- 2 核 2GB 服务器只承担认证、元数据和任务控制，不运行视觉模型，也不长期代理大图流量。

## P0：虚拟穿搭质量与遮挡专项

当前 FASHN VTON v1.5 已可在 RTX 5060 Laptop 8GB 上本地生成。常规模式继续使用 segmentation-free 路线以保持人物区域稳定；需要露出原本被衣物遮挡区域时，先完整生成服装，再按左右侧独立检查上臂、前臂和手，最后只修复核验失败的局部。

该模式只能生成合理外观，不能还原真实皮肤、纹身、伤痕、手表或饰品。产品必须保留“模型推测生成”标识，并把原图作为可随时查看的事实来源。

接下来的实现顺序：

1. 已增加扩散前语义门禁：模特叠穿参考图和人物有效区域低于约 12% 的远景图直接阻止，要求换成单件衣服图或先裁剪人物。继续用固定拒绝集统计误拦截和漏检。
2. 已完成左右上臂、前臂、手掌分别核验；继续用 30–50 组经授权的遮挡测试集校准手部清晰度、手掌宽度、手指展开和骨段比例阈值，覆盖长袖换短袖、交叉手臂、手臂贴近身体、手持物和局部出画。
3. 已完成本地 SD 1.5 Inpainting 独立手部局部修复单样例闭环：只处理失败侧、四候选择优、过滤线纹、优先参考相邻前臂肤色、手机与另一只手保护、失败自动回退。开发机实测峰值显存约 2677 MiB，四候选约 24 秒。
4. 继续完成 20 张固定集并记录 P50/P95、逐场景失败率和组合许可证；重点覆盖双手同时遮挡、交叉手臂、深浅肤色、复杂背景、贴身花纹和手持物。固定集达到门槛后再标记为商店稳定能力。
5. 保存人体解析图、姿态骨架和最终蒙版作为仅供调试的中间结果，默认不进入用户相册。
6. 增加手臂、手指、服装边缘和人物身份四项人工复核标签，记录失败原因。
7. 局部候选失败时继续自动回到干净的第一阶段结果；核验未通过的结果在界面上明确标为“未通过核验”，不能显示成完成即成功。

## P1：任务可靠性和本地资源控制

- 把试衣、植物识别、相册分类和实验室分析统一进入持久化队列。
- 支持真正中止 Python 子进程，并在下次启动时把中断任务标为可恢复或已取消。
- 显示模型加载、预处理、推理、保存四段进度；记录峰值显存和耗时。
- 磁盘不足、权重损坏、CUDA 不可用和显存不足都提供可执行的修复动作。
- 增加模型缓存上限和一键清理，但删除前显示将释放的空间。

## P1：个人相册体验

- 后台增量扫描只读取用户授权目录，使用文件标识、修改时间和哈希避免反复分析。
- 分类页继续以用户勾选的安全类别为准；低置信度、新类别和无法判断的图片进入独立未分类图库。
- 增加重复照片候选、按日期和目录筛选、批量移动分类、撤销操作和扫描状态说明。
- 不做人脸身份、证件文字、健康状况、精确位置、宗教或政治倾向等敏感推断。
- 未来云同步先做“用户主动选择的相册”，不默认同步设备全部照片。

## P1：界面与无障碍

本轮已经提高全局字号、导航、按钮高度和工作区间距。下一步加入显示缩放选项（标准、大号），再检查 125%、150%、175% Windows 缩放和 1366×768 最小窗口。

验收包括键盘导航、焦点样式、屏幕阅读器名称、颜色对比、长文本换行、加载骨架、错误恢复按钮和所有业务页的空状态。字体设置只影响界面，不改变生成图片。

## P2：植物与实验室模块

植物模块优先扩充经许可的评测数据、未知类拒识和候选证据，不急着扩大物种数量。实验室模块优先补手工增删分割对象、尺度校准记录、CSV/JSON 导出和原图/参数/算法版本追踪。两个模块都要保留“辅助分析”定位，不输出医疗、食用安全或专业诊断结论。

## 推荐执行顺序

1. sidecar 与无开发环境安装测试。
2. Windows 凭据库、正式登录门禁和服务端对象权限。
3. 长袖换短袖固定测试集、失败标签与结果对比。
4. 可取消任务队列和模型下载管理。
5. 相册增量扫描、批量整理与撤销。
6. 大号字体、缩放和键盘可用性。
7. 植物与实验室的真实数据评测和导出。

在预算很低的情况下，这个顺序能继续把重计算留在用户电脑，服务器只承担轻量控制面；真正产生持续费用的对象存储、短信、邮件和外部视觉 API 都保持按需启用。
