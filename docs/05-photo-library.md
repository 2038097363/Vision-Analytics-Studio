# 个人相册与统一素材库规划

> Windows 桌面版；日期：2026-09-14。目标是经用户授权管理设备中的照片、保护原始文件、在低资源下完成本地分类，并为其他三个模块提供素材和结果管理。目录授权、可取消后台索引、本地缩略图、分类设置、MobileNetV3 安全粗分类、单张／批量人工归类、分类图库、未分类页面和穿搭导入已有第一版代码，其余为实施规划。

## 1. 用户价值与首版范围

普通用户可按时间、标签和相册查找照片；植物观察记录、实验室素材、试穿结果都能进入同一素材系统，但保留各自的来源和单位信息。

个人相册分为“设备照片”和“应用素材”两种对象。设备照片通过系统选择器授权文件夹，只保存本机索引，不复制原图；应用素材是用户主动导入到穿搭、植物或实验室流程的副本。首版完整闭环：登录 → 授权一个或多个目录 → 选择需要的分类 → 本地索引与分类 → 分类页／未分类图库浏览 → 手动修正 → 按需导入为应用素材。

| 版本 | 功能 | 明确边界 |
| --- | --- | --- |
| P0 设备索引 | 文件夹授权、递归元数据索引、来源管理、未分类图库 | 不申请整盘权限，不跟随符号链接，不复制或上传设备原图 |
| P0.1 素材底座 | 主动复制导入、缩略图、文件名与时间索引、查看、导出 | 设备照片只有用户用于模块时才复制为应用素材 |
| P1 智能整理 | 用户选择安全分类、本地批量建议、分类独立页面、多标签、完全重复检测 | AI 标签可修改；低置信度进未分类；重复只提示不自动删除 |
| P1.1 语义检索 | 本地图文向量、以文搜图、相似图排序 | 中文查询效果独立测试，不宣称理解所有专业图像 |
| P2 扩展 | 受控目录监听、相似分组、用户开启的选定相册云同步 | 无默认全图库云同步、无人脸身份聚类 |

## 2. 桌面页面设计

相册主导航先提供“照片库、分类设置、未分类”三个独立页面。照片库管理授权来源和应用素材；分类设置让用户勾选需要的类别；未分类图库集中显示新照片、低置信度、全部分类关闭或无法可靠判断的照片。后续再加入“全部图片、我的相册、收藏、生成结果、回收站”。同一图片可以属于多个相册，不复制多份文件。

安全类别首批固定为：风景与自然、植物与花卉、动物与宠物、美食、建筑与城市、服装与穿搭、艺术与插画、交通工具。用户可全部关闭。类别集合由版本化清单维护；新增类别必须先做隐私评审、样本评测和旧版本兼容。

禁止自动推断或建立以下分类：人脸身份／姓名、民族、健康或残障、宗教与政治倾向、性取向、证件与账号、财务状况、聊天内容、家庭住址与精确位置。首版不做人脸聚类、不运行 OCR、不读取 GPS 参与分类。若画面可能涉及这些内容，模型只返回“未分类”，不生成敏感标签。

顶部有导入、搜索、排序和筛选。筛选维度包括拍摄／导入日期、手动与 AI 标签、文件格式、来源模块、是否生成、是否待分析和是否缺失原文件。

网格按需加载缩略图；滚动不解码原始大图。大图查看支持缩放、方向调整的非破坏性预览、文件信息、原始文件定位和“发送到某工作区”。实验室图片不在通用相册里改写像素或标尺。

批选支持 Shift 连选、Ctrl 多选；删除按钮明确区分“从相册移除”“将库内素材放入回收站”“删除外部原文件”。首版不提供直接删除外部原文件。

## 3. 设备授权、索引与导入策略

应用使用 Windows 文件夹选择器，让用户逐个添加图片目录；不主动枚举磁盘根目录，不申请 `broadFileSystemAccess`。用户通过选择器选中的文件／文件夹不需要该广泛权限，符合 Microsoft 建议优先使用选择器或 FutureAccessList 的方式。[Windows 文件选择器](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.storage.pickers?view=windows-app-sdk-1.8)、[应用能力声明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/app-capability-declarations)

添加目录后先做元数据索引：规范化根路径、递归但不跟随符号链接、跳过系统回收站和隐藏目录、限制单次目录数与图片数。索引记录仅留本机，绝对路径不进入云同步。单文件读取错误进入失败清单，不能因一个损坏文件放弃整个来源。

应用素材默认复制导入并保留外部原图。导入前展示图片数、预估占用和目标目录；用户从设备相册选择照片进入业务模块时，也必须明确执行“导入为素材”，不能让分析任务长期持有未经说明的外部路径。

| 输入 | 处理 |
| --- | --- |
| JPEG／PNG／WebP | 解码校验、方向预览、缩略图；原始字节单独保留 |
| 二维 TIFF | 可建立素材记录；预览交给保留位深的图像层，分析使用原始数据 |
| 多页／大 TIFF | 先显示文件类型与有限预览；必须显式标明页数和当前页，不默认为普通单图 |
| HEIC／RAW／视频 | 首版显示不支持及转换建议；后续核实解码组件许可再开放 |
| 损坏或过大图 | 有界解码、失败清单；其他有效文件继续导入 |

P0 只使用文件修改时间。拍摄日期在用户单独开启“读取基础照片元数据”后解析；GPS 默认不读取、不索引、不上传，导出副本提供清理隐私元数据选项。

初始界限：单批建议 ≤1000 张，分片处理而非同时加载；缩略图尺寸和并发根据实际内存测试调整。大小与数量规则可设置，但大文件必须走流式校验或专用路径。

## 4. 本地处理流程

1. 系统选择器返回用户授权目录，Rust 主进程规范化并保存 `PhotoSource`。
2. 低优先级任务枚举允许格式，只记录路径、名称、大小和修改时间；为每轮扫描设置游标和上限。
3. 首版使用约 10MB 的 MobileNetV3 Small 官方权重处理本地缩略图，只把 ImageNet 输出严格映射到用户启用的八类；不把 EXIF、OCR 或人脸向量交给分类器。
4. 高置信度建议进入对应分类；阈值以下、多类别冲突、类别未启用和解码失败均进入未分类图库，并保留原因码。
5. 人工修正优先于模型结果，记录模型 ID、版本、阈值与修订时间；模型升级不覆盖用户确认。
6. 用户明确选择“导入为素材”后才计算完整哈希、复制到临时位置并原子提交，供其他模块使用。

初版精确搜索使用 SQLite 文件名、相册和标签索引；通过可控的文本索引支持中文分词或字符片段匹配，采用固定查询集校验。不能把英文分词器的默认效果当成中文搜索已完成。

自动分类第一选择是专门评测过的轻量本地图像分类／图文嵌入模型，按批次加载后卸载，不为了相册常驻大模型。免费视觉 API 只用于用户主动选择的单张或小批次增强，首版不把设备相册自动分类交给第三方。预算耗尽后暂停并保留进度。

模型输出只能映射到用户已启用的安全类别。任何开放文本描述都不能直接成为标签；用户确认过的标签优先级高于模型建议。

## 5. 语义搜索与重复照片

语义搜索在 P1.1 才引入本地图文嵌入候选；模型必须支持目标中文查询或有已验证的查询转换流程，并核清权重分发许可。不要把植物领域专用图文模型直接当作所有生活照片的通用搜索模型。

首轮优先评测 `OFA-Sys/chinese-clip-vit-base-patch16`，官方提供中文文本与图像嵌入示例；它是相册 P1.1 的检索候选，不作为自动命名人物的模型。对照组先用已有标签搜索，只有不足时才增加第二个通用图文模型。具体代码、权重与依赖仍需独立登记分发条件；没有候选达到中文检索门槛时继续提供标签搜索。[Chinese-CLIP 官方模型卡](https://huggingface.co/OFA-Sys/chinese-clip-vit-base-patch16)、[官方仓库](https://github.com/OFA-Sys/Chinese-CLIP)

向量规模小时用本地文件＋进程内矩阵检索。例：1 万张、512 维、float32 原始向量约 19.5MiB，不含索引与元数据；因此第一版没有部署独立向量服务器的必要。向量维数和格式由实际模型确定。

重复检测分层：哈希一致视为相同字节；感知哈希接近只提示候选；向量相似表示语义或内容接近，不用于自动删除。不同裁剪、分辨率、实验阶段和生成版本不能因为相似就合并。

“重复”页面显示大小、分辨率、路径、拍摄时间和来源；用户选择保留对象后先进入回收站。多个任务引用同一素材时保留关系完整性，不能删掉文件后留下不可读取的结果。

## 6. 数据设计与模块接口

| 实体 | 内容 |
| --- | --- |
| Asset | 工作区、原始字节哈希、格式、尺寸、位深、拥有／引用模式、状态 |
| PhotoSource | 本机授权目录、递归范围、扫描状态、游标和最后成功时间；不同步绝对路径 |
| DevicePhoto | 本机绝对路径、文件元数据、是否仍存在、分类状态；只作设备索引 |
| CategoryPreference | 用户启用的安全类别、清单版本；可同步类别 ID，不同步本机路径 |
| AssetSource | 导入路径、批次、来源模块、拍摄时间来源、来源许可备注 |
| Album / AlbumItem | 相册与素材多对多关系、排序、封面 |
| Tag / AssetTag | 标签与关系、人工／模型来源、模型版本、是否已确认 |
| Derivative | 缩略图、预览、生成结果；父素材与处理配置 |
| Embedding | 模型 ID、版本、向量位置、原素材版本、索引状态 |
| ImportBatch | 总数、成功、跳过、失败、恢复游标与错误清单 |

任务能力包括 `assets.import、assets.thumbnail、album.auto_tag、album.embed、album.find_similar`。人工建相册和检索走本地业务接口，不占 GPU 队列。

设备照片发送到虚拟穿搭时，用户必须明确选择“人物图”或“服装图”；Rust 根据设备照片 ID 校验当前索引后复制成受控素材，再把素材 ID 写入穿搭草稿。跨模块不接受界面直接提交任意绝对路径，源文件保持不变。保存试穿结果带生成标记；实验室分析保存预览及报告引用；植物观察保存识别候选和确认名称，不把模型预测直接当人工真值。

## 7. 权限、外发和免费 API

授权读取目录只覆盖用户选定范围，取消来源后停止扫描并清除该来源索引。扫描时不跟随链接跳出边界。远程链接和图片内提示不具有读取其他本地文件的权限。相册记录的绝对路径、文件夹名称和本地用户名不发送到服务器或云模型。

免费 API 默认不批量扫描整个相册。用户选择服务后预览将发送的图片数量、是否缩小、元数据处理和服务条款；需要敏感图片时坚持本地处理或明确放弃云增强。

没有免费额度、密钥失效、地区不支持时，标注任务暂停；基础浏览、手动标签、关键词搜索与导出仍可用。调用异常不能自动改用收费模型。

## 8. 回收站、备份与缺失文件

首版库内回收站暂存 30 天作为可修改默认值；清空前展示将释放的空间和受影响任务。外部原图从不随“删除库内素材”自动删除；由系统文件管理器处理外部文件。

共享文件按引用计数清理，缩略图和向量可重建，原图不可重建。模型卸载不删除照片，清理缓存不删除人工标签。跨工作区不通过去重暴露另一工作区的文件是否存在。

引用模式后续开放时，移动或拔出磁盘显示“原文件暂不可用”，保留已有标签和预览，提供重新定位；不能拿同名文件自动替换原图，需校验哈希与用户确认。

备份分为元数据备份和完整素材备份，页面明确两者差异；后台用一致性数据库快照，不直接复制正写入的数据库。恢复先到独立目录校验，再切换，不能覆盖当前图库后才发现备份损坏。

## 9. 资源预算与质量验收

| 场景 | 初始验收目标 |
| --- | --- |
| 已登录设备断网、无 GPU | 授权来源索引、浏览、手动分类、搜索和导出可用；首次注册与云同步暂停 |
| 权限边界 | 未授权目录没有访问记录；符号链接不越界；商店包无需 broadFileSystemAccess |
| 隐私分类 | 敏感标签集合为空；OCR、GPS、人脸向量均未生成；关闭类别的照片进入未分类 |
| 500 张混合测试图 | 重复导入、损坏文件、中文路径、元数据缺失均有正确统计 |
| 5000 张索引 | 首屏不等待所有缩略图，固定设备上常见筛选 P95 争取 ≤1 秒 |
| 重启恢复 | 导入过程中退出，不丢已成功素材；失败项可以单独重试 |
| 智能标签 | 在至少 100 张独立人工标注图中报告标签精确率／召回率；优先目标精确率 ≥85% |
| 语义检索 | 至少 30 条真实中文查询，报告 Top-10 人工相关比例，并和标签搜索比较 |
| 删除与备份 | 删除不影响外部原文件，跨模块引用可解释；恢复后素材数量与哈希一致 |

时延目标以缩略图和索引预热条件标注，冷导入单列。相册任务与试衣混合运行时，不出现后台标注长期占用 GPU 导致交互任务无法执行。

## 10. 实施顺序

P0 约 4–6 个工作日：目录授权、来源管理、可恢复索引、缩略图缓存、未分类图库和素材导入。P1 再约 5–7 天：分类页面、人工修正、相册／标签／回收站、失败恢复与固定测试集。本地自动分类模型评测和接入约 3–5 天；语义检索、目录监听和云同步分别作为后续独立任务。

交付物包括真实图片导入演示、导入失败清单、资源报告、删除与恢复测试记录、支持格式表和模型标签质量报告。先让照片管理可靠，再增加智能功能，不用“全部自动分类”掩盖找不到文件或误删原图的问题。
